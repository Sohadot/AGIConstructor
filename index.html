Component Audit Protocol

Whatever form general intelligence takes, it will have been constructed. Every component is auditable.

Asking whether a system is AGI resolves into argument, because the definition is contested. Asking which components it has built resolves into evidence. ACL-1.0 is the protocol for producing that record — and for stating plainly what could not be verified.

The instrument

An unfilled ledger

Eight components. Every audit assigns each one a state and an evidence tier — no exceptions, no partial ledgers. Open a row to see what it asks and what disqualifies a claim.

How a row is filled

States and evidence

Constructed
Demonstrated at Tier A or B, repeatably, with no disqualifier present.
Partial
Present but bounded — limited domain, limited persistence, or degrades under repetition.
Claimed
Asserted at Tier C or D only, or contradicted by a disqualifier.
Absent
Not present, or present only as stated intent.

No component reaches Constructed on a single demonstration. Performing once is not construction; performing reliably is.

Tier A
Independent reproduction by a party with no commercial interest in the result.
Tier B
Developer disclosure with reproducible method, code, or open evaluation artifacts.
Tier C
Developer disclosure without reproducible method — technical report, system card.
Tier D
Marketing material, demonstration video, executive statement.

A component's state is capped by its best available evidence. Tier C and D cannot support Constructed, however confident the claim.

Stated limits

What ACL does not measure

  • Safety, alignment, or risk. An independent axis. A complete ledger says nothing about either.
  • Capability level. Eight constructed components is not "more capable" than five. The ledger records construction, not performance.
  • Proximity to general intelligence. ACL sets no threshold and takes no position on whether one exists.
  • Component quality. Constructed means present, repeatable, and evidenced. Not good.
  • Sufficiency of the component set. Eight components reflect current architecture. Additions are expected, and will be versioned.

A ledger is a record of what was found. It is not a conclusion about what the system is.

Independent use

Run an audit

ACL-1.0 may be applied, cited, and published by anyone. No registration, no notification, no permission. Derived ledgers need not be shared.

  1. Fix the object — name the exact system and version. A ledger is void if the object shifts.
  2. Collect the claim set for all eight components, with source and date.
  3. Assign the evidence tier before assessing the claim, never after.
  4. Check disqualifiers first. A disqualifier caps the state at Claimed.
  5. Test repeatability where access permits. Where it does not, record an access limit — not an absence.
  6. Publish with boundary cases and access limits attached.
